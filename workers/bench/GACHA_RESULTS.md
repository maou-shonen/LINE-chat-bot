# 抽卡 CPU

兩選項的一萬抽，在 workerd 裡 p95 是 1.0 ms。門檻是 10 ms。沒有改抽卡演算法。

量測跑在 `npm test` 的 vitest workerd isolate。沒有量 minify 後的部署 bundle，因為這支 PR 不部署。機器 16 核。量測開始時 load average 是 0.71、0.70、0.48。

每個樣本是一批呼叫的平均。這個 isolate 的 `performance.now` 步進約 1 ms。一萬抽一批 10 次，步進落到每次約 0.1 ms。單抽要一批 200 次才離開 0。單抽數字只表示它低於約 0.01 ms。

## 一萬抽

回覆是 `a__b`。訊息是 `cap*10000`。random.org 回 10000 個 0，所以每一抽都命中第一個選項。回覆不是 `a x 10000` 就記成錯誤。錯誤數是 0。

31 個樣本，每個樣本 10 次。

|  | ms |
| --- | --- |
| p50 | 0.9 |
| p95 | 1.0 |
| max | 1.1 |
| min | 0.8 |

同一次執行裡，5000 抽的 p50 是 0.4 ms，p95 是 0.5 ms。次數減半，時間約減半，差距在 1 ms 步進以內。時間跟著抽數走。瓶頸是這一萬次的迴圈，以及 random.org 回應的拆行。

前一次同樣的一萬抽，p95 是 1.2 ms，min 0.9 ms，max 1.3 ms。兩次都在 1 ms 附近。

## 較長的池

20 個 `%0.5` 選項。每一抽的亂數是 10，會把 20 個權重都走完。回覆必須是 `o19 x 10000`。21 個樣本，每個樣本 10 次。p50 是 2.2 ms，p95 是 2.6 ms，max 是 2.8 ms。

比兩選項的第一命中多約 1.3 ms。池子變長，時間會增加。這次沒有量超過 20 個選項的池。

## 常見情況

單位是 ms，欄位是 p95。單抽、加權單抽、保底、種子、百分比都在 0.01 或以下，貼著計時器步進。10 抽是 0.02。100 抽是 0.05。這些是上限。
